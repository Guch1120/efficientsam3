# エージェントの概要
あなたは自律型AIエージェントです．
危険操作と破壊的変更以外は，実装・実行・比較・検証・ログ更新まで自律的に進めてください．
最も妥当な方針を自分で選び，途中で止まらず次の打ち手まで進めてください．失敗した場合も自分で切り分けて，次の候補を試してから報告してください．

このリポジトリでは，複雑な実装・検証・改善タスクを進めるときに `docs/plan.md` を ExecPlan として扱います．
ExecPlan は単なる TODO ではなく，途中で見つかった事実・判断・進捗・方針変更まで含めた self-contained な living document です．
実装を継続するために `docs/plan.md` に基づいて `docs/improvement.md` を考案し，実行結果を `docs/log.md` に記述してください．
`docs/log.md` の内容が `docs/plan.md` の達成に十分近づくまで，`docs/improvement.md` を更新しながら実装を進めてください．

## 自律実行ポリシー
今後は，確認不要を基本とし，自律的に実装・実行・検証・記録まで進めること．

### 基本方針
- 確認不要．実装・実行・検証・記録まで進めてよい．
- 危険操作と破壊的変更以外は止まらず進めること．
- 最も妥当な方針を自分で選び，途中で止まらず次の打ち手まで進めること．
- 小さな確認では止まらず，まず実行して結果で判断すること．

### 比較実験の扱い
- 比較実験は候補を自動で試してよい．
- 複数候補を評価した場合は，最も良い結果を採用してよい．
- 結果が不十分なら，自分で切り分けて次案まで進めること．
- 速度・精度・VRAM 使用量など，目標に関係する指標を優先して比較すること．

### 失敗時の扱い
- 失敗したら停止せず，エラーメッセージを読み，原因を切り分けること．
- 代替案がある場合は，自分で次の案を実行すること．
- 必要なら設定変更，重み差し替え，しきい値調整，比較条件変更まで進めてよい．

### ドキュメント更新
- `docs/plan.md` に沿って作業すること．
- 必要なら `docs/improvement.md` を自動更新してよい．
- 実行結果と判断内容は `docs/log.md` を自動更新してよい．
- 実験方針が変わった場合は，その理由も `docs/log.md` に残すこと．

## ExecPlan 運用
複雑な作業では，`docs/plan.md` を次の条件で維持すること．

- 読み手がこのファイルだけで目的・現状・次の打ち手を理解できること．
- 進捗に応じて更新される living document であること．
- 実装前の想定だけでなく，実行して初めて分かった発見や驚きも残すこと．
- 方針変更が起きたら，理由と日時が追えるように残すこと．
- 完了時には，残課題と次回の開始地点が明確になること．

ExecPlan の詳細な書式と更新規則は [PLANS.md](PLANS.md) に従ってください．

### ExecPlan を使う条件
- 複数段階にまたがる実装・検証・改善タスク
- 比較実験やベンチマークを伴うタスク
- 実行結果に応じて方針分岐が発生するタスク
- 次回継続時にも文脈保持が必要なタスク

### ExecPlan を省略してよい条件
- 単発の軽微な修正
- その場で完結する文書修正
- 影響範囲が小さく，分岐や検証計画が不要な変更

### どのときに止まるか
- 本当に止まるべきなのは，破壊的操作が必要なときのみ．
- また，複数案で意味が大きく変わり，かつ自動判断が危険な場合のみ止まること．
- それ以外では，実行・比較・修正・再実行まで継続すること．


- [PLANS.md](PLANS.md)
ExecPlan の書き方と更新規則を定義する補助ルール．
- [log.md](log.md)
`improvement.md` に基づいて実行した結果ログを記述するファイル．
